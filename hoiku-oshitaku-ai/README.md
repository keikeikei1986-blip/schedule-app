# 保育園おしたくAI（MVP）

3〜6歳の保育園児が、AIの「優しいお姉さん」と会話しながらゲーム感覚で朝の準備を進める
Webアプリです。ビルド不要・素のHTML/CSS/JavaScriptのみで動作し、データはブラウザの
`localStorage` に保存されます（このリポジトリの他アプリと同じ構成方針）。

## 起動方法

```bash
python3 -m http.server 8420
```

その後 `http://localhost:8420/hoiku-oshitaku-ai/` を開いてください。
（このリポジトリのルートに `.claude/launch.json`（`static-server`）があるので、
Claude Codeのプレビュー機能から起動することもできます）

`index.html` を直接ブラウザで開いても動作しますが、音声認識（Web Speech API）は
ブラウザによって `https://` または `http://localhost` 等のセキュアコンテキストを
要求するため、可能な限りローカルサーバー経由で開いてください。

## 使い方

1. **スタート画面**：優しいお姉さんが挨拶してくれます。「🌞 朝の準備をはじめる」をタップ。
2. **AI会話画面**：お姉さんが1つずつミッション（トイレ・着替え・朝ごはん…）を話しかけます。
   子どもは基本的に何も操作せず、話しかけられたら**声で答えるだけ**で進みます
   （AIが話す→自動でマイクが開く→子どもが話す→AIが認識して返事する→また自動でマイクが
   開く…というループ。詳しくは下記「会話の続けかた」）。
   - うまく認識できない／対応していない端末のために「✅ できた！」「⏳ まだだよ」
     「❓ わからない」ボタンと🎤ボタンも常設（フォールバック）
   - 「できた！」のたびに右上のミニパズルが1ピースずつ完成していく
3. **パズル完成画面**：全ミッション終了で虹のパズルが完成し、「保育園に行こう！」で終了演出。
4. **設定画面**（スタート画面右上の⚙️）：
   - 子どもの名前
   - 使うミッションのON/OFF
   - ▲▼ボタンでミッションの順番を入れ替え

## 現在実装されている機能

- 会話フロー一式（挨拶→ミッション×n→パズル完成→「保育園に行こう」）
- Web Speech API による音声認識（`ja-JP`）と音声合成（お姉さんのセリフ読み上げ）
  - 非対応ブラウザ／認識失敗時もアプリは止まらず、画面上のボタンで進行できる
- **女性の声を自動選択**：`js/voice-engine.js` がブラウザの持つ日本語音声一覧から、
  名前に含まれるキーワード（`Kyoko`/`O-Ren`/`Ayumi`/`Haruka` 等、macOS/Windows/
  Chromeでよく使われる女性音声名）でスコアリングし、もっとも「お姉さんらしい」
  女性音声を選ぶ。見つからない場合は日本語音声の先頭にフォールバックする
  （Web Speech APIには性別の標準プロパティが無いためのヒューリスティック）。
- **会話が途切れないための工夫**：「褒め言葉」と「次のミッションの質問」を2回に
  分けて読み上げず、1つの発話として連結して読み上げる
  （例：「できたね！すごい！　じゃあ次はお着替えだよ、着替えられるかな？」）。
  待ち時間や無音の間を極力挟まず、ひとつながりの会話として聞こえるようにしている。
- **できるだけ操作なしで続く音声ループ**：AIの発話が終わると、少し間（0.4秒）を
  置いて自動的にマイクが開く。子どもがマイクボタンを押さなくても、「話しかけら
  れたら答える」だけで会話が連続する。ブラウザの制約上、常時接続の音声チャンネル
  を維持することはできないため、「1ターンごとに自動でマイクを再オープンする」
  という形で疑似的に連続会話を実現している（詳しくは下記の技術的な制約を参照）。
- **想定外の発話への対応（簡易）**：「できた/まだ/わからない」のどれにも当てはま
  らない発話は、内容に応じたひとこと相槌（雑談・年齢の質問・お菓子の話・お友達の
  話などをキーワードでゆるく検知）を返してから、さりげなく今のミッションの質問へ
  戻る。同じミッション内で相槌が3回続いたら、ループを止めてボタン操作に案内する
  （無限に脱線につきあわないためのセーフティ）。
- 聞き取れなかった場合は1回だけ「もう一回いってごらん？」と優しく聞き返し、
  それでもダメならボタン操作に静かにフォールバックする（何度も催促しない）。
- キーワード一致による簡易な発話判定（モックAI、`js/voice-engine.js` の
  `interpretAnswer` / `craftOfftopicAck`）
- ミッションごとに褒め言葉・待つときの声かけ・ヒントをランダム表示
- ミッション1つクリア＝パズル1ピース。ミニパズル（会話画面）→フルパズル（完成画面）
- 親向け設定（名前／ミッションON-OFF／並び替え）を `localStorage` に永続化
- スマートフォン優先のレイアウト（大きい文字・大きいボタン）

## 会話の続けかた・技術的な制約について

ブラウザの `SpeechRecognition` API には、人間同士の通話のような「常時接続で
双方向に聞き続ける」機能は無く、1回の発話を認識したら区切って止まる仕組みに
なっている。このアプリでは、AIの発話が終わるたびに自動でその「1回ぶんの認識」
を開始し直すことで、子どもがマイクボタンを毎回押さなくても会話が続いているように
体験できる設計にしている（＝完全な常時接続ではなく、ターンごとの自動再オープン）。

また、多くのブラウザ（特にiOS Safari）は音声の再生・認識の開始に「ユーザー操作
（タップ）」を必要とするため、セッション中に音声が使えるのは基本的に最初の
「朝の準備をはじめる」タップ以降に限られる。それ以降は上記の自動ループで進み、
子どもが追加でタップする必要があるのは、対応していない端末や聞き取れなかった
ときのボタン操作のみ。

## 今後、本物のAI音声会話を実装する場合に必要なもの

`js/voice-engine.js` に接続ポイントをまとめてあります。

- `AI_CONFIG.provider` / `AI_CONFIG.endpoint`：モック判定ではなく本物のAI（LLM等）に
  差し替える場合、自前のバックエンド（APIキーはサーバー側で保持し、クライアントには
  一切書かない）のエンドポイントをここに設定する。
- `interpretAnswer(transcript)`：現在はキーワード一致。バックエンド経由でLLMに
  「子どもの発話→できた/まだ/わからない、もしくは自由な返答」を判定させる関数に
  差し替え可能な形にしてある。
- `craftOfftopicAck(transcript)`：現在はキーワード一致の相槌。本物のAIに差し替える
  場合、ここを「直前の会話文脈つきでLLMに自由な受け答えを生成させる」関数にすると、
  「昨日アイス食べた！」→「何味だったの？」のような、内容に即した自然な返答が
  できるようになる（会話履歴を渡せるよう、呼び出し側の `app.js` を軽く拡張する
  必要はあるが、戻り値の契約＝文字列を返す、は変えなくてよい設計にしてある）。
- `speak(text)`：現在はブラウザ標準の `speechSynthesis`＋女性音声の自動選択。より
  自然で高品質な声にする場合は、バックエンド経由でTTS APIの音声ファイルを取得し
  `<audio>` で再生する形に差し替える（こちらもAPIキーはサーバー側のみで保持）。
- `listenOnce()`：現在はブラウザ標準の `SpeechRecognition`。より高精度な音声認識API
  （サーバーサイドでの音声解析等）に差し替える場合も、`onResult`/`onError` のコール
  バック契約はそのまま流用できる。将来、真の常時接続（ストリーミング音声認識）に
  対応する場合は、`app.js` の「1ターンごとに `startListening()` を呼び直す」仕組み
  を「ストリームを開始し、区切りなく `onResult` を受け取り続ける」形に置き換える
  ことになる。

`js/app.js` 側はこれらの関数を呼び出すだけの設計なので、上記の差し替えを行っても
画面遷移・進行ロジック・パズル演出には手を入れる必要はありません。

## 今後の改善候補（MVP範囲外）

- 真の常時接続（ストリーミング）音声認識への対応
- 会話履歴を踏まえた、より自然な雑談応答（本物のLLM接続が前提）
- 途中経過（今日どこまで進んだか）のセッション永続化（現状はページ再読み込みで
  最初から）
- パズルの絵柄を複数用意して日替わりにする
- ミッションごとのイラスト／アイコンの充実
